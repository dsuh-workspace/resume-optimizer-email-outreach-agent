ApplyPilot 0.4.0 autofill verification — 2026-10-05

Scope and fixed acceptance criteria
Hosted Greenhouse and Lever. The 29-field matrix is acceptance-matrix.json.
It covers explicit identity, country, authorization, current/future/inverted
sponsorship, school autocomplete, degree, major, separate start/end month/year,
race, Hispanic identification, gender, disability, protected and general veteran
status, checkbox disclosures, approved text-input and textarea answers, preserved
email, and intentional manual cases (foreign authorization, completed degree,
unknown calendar day, consent and signature).
Expected results were set before the end-to-end runs. Mandatory supported fields
could not be counted as passing merely by becoming manual.

Public form observations (read only; no public forms filled)
Greenhouse: https://job-boards.greenhouse.io/accelschools/jobs/7660773003
Observed split school/degree/discipline and month/year controls, authorization,
voluntary disclosures, and separate consent/attestation questions.
Lever: https://jobs.lever.co/nomihealth/ae785bbe-22df-4ea9-8159-a807175c0f85/apply
Observed sponsorship/authorization radios, short responses, demographic selects,
and ethnicity checkbox groups. Fixtures independently reproduce these patterns;
they are not complete copies or certifications of these employers' applications.

Results
- Python suite: 182 tests, zero failures/errors; one opt-in HTTP test skipped in
  that suite, then run separately and passed.
- Existing mapping suite: 24 tests passed. Expanded fixed-matrix mapping passed,
  including missing facts, incompatible options, country boundaries and ambiguity.
- Worker sender/origin/route/tab/revision/revocation checks passed.
- Synthetic browser regressions: 23 assertions each on Greenhouse and Lever;
  side-panel approval, editing, cancellation/recovery and stale-tab tests passed.
- Actual unpacked extension: all 29 independent page-value assertions passed
  before and after recovery in each of Greenhouse immediate/delayed/rerender and
  Lever immediate/delayed/rerender. Separate Greenhouse button-dropdown challenge
  also passed. All seven runs used fresh isolated Chrome profiles and fixture
  backend data, intercepted portal requests, and synthetic candidate preferences.
- Each acceptance run forced first and last name to fail, verified diagnostics
  exclude answer values, reloaded into a new panel document, rescanned, selected
  only the failed empty fields, and verified their recovery. Later email edits
  remained intact. Restored written answers required fresh approval.
- Full original loaded-extension regression passed in disposable code copy
  /private/tmp/applypilot-coverage-copy-su3hwpkj: cold native startup, toolbar
  permissions, PDF/evidence selection, upload acknowledgement, 32-second job
  across panel restart, full Chrome restart, revocation and native reconnect denial.
- No Next clicks, submissions, production application fills or Gmail operations.

Issues actually discovered and corrected
A dropdown replaced its input when opened; the adapter now reconnects only to
one replacement with an identical verified fingerprint. Delayed and replacement
control tests verified the fix. A test reload race initially observed the old
panel; a document marker now proves diagnostics load in a new panel instance.
The real-model smoke batch covered three synthetic questions and character limits
180/300/450. All responses passed citation/metric/length validation. Manual review
found the third response overstated listed coursework as completed. The prompt
was tightened and just that question rerun: it now describes pursuing the degree
and coursework including Analytics. All three reviewed final responses were
relevant and grounded in the supplied synthetic evidence. Four AI generations
were used in total. No real candidate profile or disclosure answers were sent.

Artifacts and reproducibility
The test commands are in ../README.md. Per-run logs are in /private/tmp using
applypilot-* names; these are transient. The acceptance matrix and scripts are
retained here for repeatable checks. Live AI smoke is explicitly invoked and
excluded from offline regressions. Existing loaded-extension regression renders
icons, so it was executed in an isolated code copy; the new acceptance runner
only writes temporary fixture data.

Limits
No claim of universal employer widget coverage. Custom sites, frames, ambiguous
options, missing facts, exact days not recorded, complete work history, consent,
attestations and CAPTCHA can remain manual. Additional education rows must be
added on the employer page before rescanning. Checkbox-group undo, uploads and
custom-dropdown undo require manual restoration. Use-once answers last only in
the current panel session. Disclosures and factual answers are user-provided,
not independently verified. Listed source evidence and numeric validation cannot
prove every AI paraphrase. Version 0.4.1 removes approval at the user's request; it does not strengthen those semantic guarantees. Retained page values do not
prove the employer's server has saved an application. The two original failures
were not recoverable retrospectively; the new diagnostic history addresses future
attempts without storing answer values.
